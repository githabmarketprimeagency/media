Méthodologie pour developper un micro service 


1 - Créer le contrat d’interface en utilisant le standard Open API et le format yaml de préférence.

2 - Copier le dossier boilerplate_pour_bolt en lui donnant le nom qu’on souhaite pour le micro service.

3 - Placer le contrat d’interface dans le repertoire suivant :

ui/src/main/resources/openapi.yml

4 - Renommer les dossiers suivants en utilisant le nom du micro service à la place de « boilerplate » :

- domain/src/main/java/com/microservice/boilerplate/
- infrastructure/src/main/java/com/microservice/boilerplate/
- ui/src/main/java/com/microservice/boilerplate/
- usecase/src/main/java/com/microservice/boilerplate/

5 - Rechercher et remplacer dans le projet toutes les références à :

com.microservice.media -> com.microservice.$nommicroservice

6 - Créer une branche locale nommée feature/v1.0 et la pousser sur un github privé.

7 - Importer le projet dans Bolt.new et se placer sur la branche feature/v1.0

8 - Lancer le prompt recherche_entites_openapi.txt pour trouver toutes les entités présentes dans l’OpenApi, conserver la liste des entités trouvées dans l’ordre fourni par Bolt et ignorer les entités dont le nom commence par « Full »

9 - Générer les endpoint API de la première entité fournie par Bolt :

    A - Lancer le prompt generation_des_endpoints_pour_une_entite.txt en remplaçant le textes
     
        /$endpoints par le vrai endpoint de base correspondant à l’entité.

        par exemple -> /entities
     
    B - Tester les endpoints générés
    
10 - Répéter l’étape 9 jusqu’à ce que tous les endpoints soient générés pour les entités.

11 - Lancer le prompt suppression_elements_par_defaut_concernant_requestcheck.txt

12 - Lancer le prompt mettre_a_jour_references_et_readme.txt pour mettre à jour les références à boilerplate et le readme du projet.

Il faut au préalable remplacer $nouveaumicroservice par le nom du micro service
